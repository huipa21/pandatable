## Binding contracts to preserve

- **View config** (`meta.views.config`, doc 08 §1) already stores
  `{"fields":[{"id","visible","width"}],"frozen":N,"rowHeight":"short"}`.
  `meta.views` already has `version`, `locked`, `scope`, `owner_id` and
  `position`; no migration is needed. Field order in `fields[]` is display
  order. Deleted/unknown field IDs are dropped silently on read and cleaned on
  the next save. Config updates use optimistic concurrency with
  `If-Match: <version>`; a stale version is 409 `ERR_VERSION_CONFLICT` and the
  client reloads and re-applies.
- **Query contract is unchanged.** `POST /views/{id}/query` keeps offset
  0..1,000,000, limit default 100 (1..100), optional single typed sort,
  `includeCount` and the transient D-138 `fieldIds` override that persists
  nothing. Visible configured live fields keep their order, duplicates/unknown/
  deleted IDs are ignored, omitted live user fields append in metadata order
  and system fields stay hidden unless explicitly visible.
- **Rows/codecs are unchanged.** The 12 writable batch-1 kinds and five
  read-only system kinds, canonical wire values (bigint/decimal strings, UTC
  instants, select labels), per-field codecs, atomic bounded bulk operations
  and the existing body limits stay exactly as they are. Do not add a parallel
  validator, a row version or a second grid provider.
- **Permissions.** Read requires effective table read; persisting view config
  requires write or owner on the table. Admin has no data bypass. Hidden,
  missing or trashed resources are 404; visible but insufficient access is 403.
  Personal views belong to their owner only (404 otherwise). Reauthorize
  uncached under the existing D-080/D-099 locks; keep the three-second lock
  timeout mapping to `ERR_DDL_LOCK_TIMEOUT` and repeatable-read serialization
  to `ERR_SCHEMA_CHANGED`.
- **Transport.** Mutations need exact Origin, `X-PT-CSRF: 1`, bounded
  known-member JSON, `no-store` and ten-second deadlines. Forced password
  change is 403; disabled/unauthenticated is 401. Errors stay translated,
  redacted and correlated. Static metadata SQL uses sqlc; dynamic data SQL uses
  Squirrel with validated metadata and `pgx.Identifier`. No physical names in
  DTOs.

## Implement T1.21

- Add `PATCH /views/{id}` **restricted to the column subset** of the config:
  the ordered `fields[]` with `visible` and `width`, plus `frozen`. Validate
  server-side against current live fields, reject unknown members, enforce
  bounded width and `0 <= frozen <= visible column count`, require
  `If-Match: <version>` and bump `version` exactly once per accepted save.
  Reject name, scope, locked, position, filter, sort, group, highlight,
  aggregates, form, kanban and calendar payloads here: those are T2.10/M2.
- Persist grid column resize, reorder, hide/show and freeze for users with
  write/owner on an unlocked view. Readers, locked views and any view the user
  may not write keep the existing **local-only** behavior, with no request and
  no pretend "saved" state. Replace the session-local `fieldOverride` path with
  this contract without changing the transient `fieldIds` query override.
- Saves must be debounced/coalesced, cancellation- and generation-guarded, and
  must not block editing or scrolling. A rejected or conflicting save reloads
  the authoritative config, re-applies the user's intent where still valid and
  shows a translated failure; never leave optimistic state after a failed save.
- Complete the keyboard map in `docs/12-frontend.md` §4 for the production
  grid: arrows, Tab/Shift+Tab, Enter (edit / commit+down), Esc (cancel), F2,
  Delete/Backspace (clear), Ctrl/Cmd+C/V/X, Ctrl+D, Ctrl+A, Shift+arrows,
  Space (expand row / toggle checkbox), Home/End, Ctrl+Home/End and
  PageUp/Down. Keep D-139 virtual-index mapping: DOM/RevoGrid viewport indexes
  are never global row offsets. Clearing a cell is an ordinary bounded codec
  write; read-only, computed and system columns are skipped, not failed.
- Keep the grid, editors and registry lazy; the initial shell must stay free of
  grid imports and under the 600000-byte gzip budget. Keep paging bounded at
  100-row pages and <= 300 cached rows. Mobile cards (< 768 px) must not mount
  RevoGrid; column ops are a desktop capability and must degrade honestly.
- Use `web/src/api` types/request helpers, memory-only state, translated safe
  errors and matching static en/zh-CN keys. No user-visible string in source.
- Do not add comments/history, uploads, relations/formulas, filters, sort UI,
  grouping, highlight, search, view create/rename/duplicate/lock, trash/restore,
  realtime, API tokens, external integrations, self-registration, public
  sharing or SSO. Controls must not imply unimplemented features work.
