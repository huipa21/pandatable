### 2.2 `tools/ptdev` (stdlib only, no third-party deps)
Structure suggestion: `main.go` (command dispatch + help), `engine.go`, `execx.go` (run commands, stream output, echo the command line), `db.go`, `build.go`, `lint.go`, `test.go`, `version.go`, with unit tests.

Commands to implement now:

| Command | Behaviour |
|---|---|
| `help` (default) | List commands with one-line descriptions; show detected engine. |
| `version` | `git describe --tags --dirty --always`; if no tags → `0.0.0-dev+<shortsha>[.dirty]`; if git unavailable → `0.0.0-dev`. Strip leading `v`. |
| `engine` | Print detected engine and how it was chosen. |
| `db up` | Ensure dev PostgreSQL 18 container `pt-dev-db`: start if it exists, else run `docker.io/library/postgres:18` with `POSTGRES_PASSWORD=postgres`, `-p 127.0.0.1:55432:5432`, volume `pt-dev-pgdata:/var/lib/postgresql`. Wait (≤ 60 s) until `<engine> exec pt-dev-db pg_isready -U postgres` succeeds. Print the DSN `postgres://postgres:postgres@127.0.0.1:55432/postgres?sslmode=disable`. |
| `db down` | Stop the container (keep data). |
| `db reset` | Remove container and volume (ask for confirmation unless `--yes`), then `db up`. |
| `db status` | Running/stopped/absent + DSN. |
| `db psql` | Interactive `psql` inside the container (stdin/stdout attached). |
| `build` | If `web/package.json` exists → run web build (pnpm) and copy `web/dist` → `internal/web/dist`; otherwise print "web: skipped (no web/ yet)". Then `go build -trimpath -ldflags "-s -w -X main.version=<ver>" -o bin/pandatable[.exe] ./cmd/pandatable`. Flag `--linux` cross-compiles `GOOS=linux GOARCH=amd64 CGO_ENABLED=0` to `bin/pandatable-linux-amd64`. |
| `lint` | `gofmt -l .` (fail if any file listed), `go vet ./...`, `golangci-lint run` if on PATH (else print a warning with install hint, not a failure); web lint only if `web/package.json` exists. |
| `test` | Unless `--no-db`: run `db up` and export `PT_TEST_DATABASE_URL` (DSN above) to the child process. Run `go test ./...` (pass through `-run`, `-v`, `-count` flags). Web tests only if `web/` exists. |
| `check` | `lint` → `test` → `build`; print a summary table with pass/fail per step and total duration; non-zero exit on any failure. |

Commands that belong to later tasks must exist in help but print `not implemented yet (Tx.y)` and exit 2: `dev` (T0.4/T0.5), `web build` (T0.5), `e2e` (T0.7), `image build` / `image save` (T0.6), `deploy` (T0.6).

Engine detection (from docs/14 §2): `PT_ENGINE` env (`podman`|`docker`, anything else = error) → else `podman` if on PATH → else `docker` → else a clear error for commands needing an engine (`version`, `lint`, `build`, `test --no-db` must still work without an engine). Implement detection with an injectable `lookPath` so it is unit-testable.

Cross-platform requirements:
- Use `os/exec` directly (never `sh -c` / `cmd /c`), `filepath` for paths, `.exe` suffix on Windows for `go build` output.
- Ctrl+C must stop child processes cleanly (`signal.NotifyContext`).
- Colors optional; must degrade gracefully (respect `NO_COLOR`).
- Exit codes: 0 ok, 1 failure, 2 usage / not implemented.
