  `POST /workspaces/{id}/books`, `PATCH|DELETE /books/{id}`,
  `POST /books/{id}/tables` (returns the full table schema),
  `PATCH|DELETE /tables/{id}`, `GET /tables/{id}/schema`. Mutations need
  `X-PT-CSRF: 1` + exact Origin, JSON <=4096 bytes with unknown members rejected,
  and return an opaque `eventId` (no realtime exists; refetch `/nav` instead).
  Responses are no-store. A malformed UUID is 404.
- `/nav` returns `{workspaces:[{id,name,icon,color,createdAt,level,pathOnly,
  books:[{id,name,position,level,pathOnly,tables:[{id,name,position,
  schemaVersion,level,views:[{id,name,type,scope}]}]}]}]}`. `level` is
  none|read|write|owner; `pathOnly` workspaces/books (level `none`) only hold
  visible descendants - show them as breadcrumb context, with no settings/create/
  rename/delete controls and no sibling content. The admin role has no special
  case: a fresh admin's tree is empty and the admin sidebar entry stays a
  separate role-guarded link. Order is already deterministic (workspaces by
  creation, books/tables by position then id); do not re-sort client-side.
- Permissions the UI must mirror (never invent access, the server re-checks):
  workspace PATCH/DELETE and book create/rename/reorder/delete need effective
  **owner of the workspace**; table create/rename/reorder/delete need effective
  **owner of the book** (workspace owners inherit it). A book owner therefore
  sees "new table" on its book but no rename/delete on the book itself; a
  table-only user sees a path-only workspace/book with just that table.
  Any active user may create a workspace and becomes its direct owner. 403 means
  visible-but-insufficient, 404 hidden/trashed/deleted concurrently (refetch nav,
  show the localized not-found/removed state, never reveal existence).
- Names: trimmed 1..100 code points without control characters; workspace icon
  <=16 code points and color `#RRGGBB` (both nullable; null clears). Display
  names are not unique and renames are metadata only. Reorder is
  `PATCH {index}` = zero-based target index among the *other live siblings of the
  same parent* (books within a workspace, tables within a book); workspaces have
  no position and cannot be reordered. Out-of-range is 400, an unchanged index is
  a 200 no-op. There is no cross-parent move.
- Soft delete (D-036): `DELETE` hides the target and descendants at once and keeps
