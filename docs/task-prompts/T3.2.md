## Scope

- Implement per-table, in-memory presence on the existing authenticated WebSocket hub; pass AT-604.
- Broadcast presence at most 4 times per second per table; expire stale users after 60 seconds without heartbeat.
- Client reports table open, view switch, and cell-focus changes, throttled to 200 ms.
- Show collaborators in a table-header avatar stack and show another user's focused cell with a colored outline and name tag.
- Add/update focused unit and E2E coverage, including two users observing entry, focus, and departure.

Out of scope: persistence or multi-instance presence, comments/notifications, and changes to row-edit conflict behavior.

## Contracts to respect

- Presence state is process-local and scoped to a subscribed table. Reuse T3.1 authentication, subscription, ACL rechecks, and socket lifecycle; never expose presence to unauthorized table subscribers.
- Follow the existing WebSocket `{ "t": type, ... }` envelope. Keep presence payloads minimal; do not broadcast unrelated row or user data.
- Remove disconnected users promptly where possible and expire missed heartbeats within the documented 60-second bound.
- Follow frontend conventions: user-visible text must use both `en` and `zh-CN` i18n catalogs; match existing theme and responsive behavior.
- Do not add a dependency without justification.
