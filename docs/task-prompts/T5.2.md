## Scope

- Implement AT-904: admin-managed SMTP settings and test mail; logged-out
  self-service password reset by email; user-controlled opt-in mention email.
- Extend the existing settings, auth, comments/mentions, and notification
  surfaces where appropriate. Preserve existing admin password reset and
  in-app notification behavior.
- Add focused backend/frontend tests and an AT-904 E2E spec that exercises the
  complete mail flow against a local test SMTP sink; tests must not depend on
  an external mail provider or deliver real mail.

## Out of scope

- SSO, self-registration, external integrations other than configured SMTP, or
  changing in-app notification semantics.
- Replacing/removing the existing administrator password reset, or recovery
  by username or any channel other than the account email address on file.

## Contracts to respect

- D-008 reserves self-service reset and mention email for M5, but its
  admin-only reset policy must be superseded by a new D-xxx decision for the
  self-service flow. Reuse the bounded password worker and canonical hashing
  policy (D-074); successful reset must revoke sessions. Define reset-token
  lifetime, single-use/storage, expiry behavior, and non-enumerating request
  responses; never log or persist raw tokens.
- SMTP settings and test-mail actions are admin-only. Never return SMTP
  credentials from reads, expose them in logs/errors, or overwrite a stored
  secret merely because an edit omitted it. Define secret storage/configuration,
  validation, and delivery-failure behavior in a new D-xxx if not already
  settled. Test mail must clearly report success/failure without exposing
  credentials.
- Mention email is disabled by default and user-opt-in. Send only for newly
  resolved, eligible mentions after the comment transaction commits; exclude
  the author and preserve D-185's active-user, effective-table-read-access,
  and recipient notification rules. Mail delivery failure must not roll back
  comments or in-app notifications. Avoid leaking content/access in recipients,
  message bodies, URLs, or logs; use safe localized links.
- Follow existing auth/API error, ACL, CSRF/Origin, request-size, timeout,
  rate-limit, session-revocation, and no-store conventions. Reuse existing
  user email normalization/validation. Update relevant API, data/deployment,
  and frontend docs plus AT-904 evidence.
- All visible strings and errors need matching `en` and `zh-CN` keys; support
  dark mode, keyboard/touch use, and 390 px width.
