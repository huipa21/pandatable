### Actual codec / field / schema / DDL contracts

- **Go `internal/codec`**
  - `Lookup`, `Kinds` and `Bind(kind, json.RawMessage)` return a bound
    `Field`. It has canonical Options, ReadOnly, Column, Constraints, Decode,
    Encode, ParsePaste, FormatText, DefaultValue, FilterOps and Aggregates.
  - Batch 1 only: text, long_text, integer, decimal, float, checkbox, date,
    datetime, single_select, multi_select, email, url, plus five read-only
    system kinds.
  - Never interpolate raw PGType, options, expressions or physical names.
  - Use `Decode` for every row write and `Encode` for every read.
  - `codec.APIError` maps to 400 `ERR_VALIDATION` with safe
    `details.reason/option`. Unsupported scans stay server errors.
- **D-115 wire values**
  - bigint and row id: canonical decimal strings
  - decimal: fixed-scale strings, precision ≤38, excess nonzero fraction
    fails
  - small/int: numbers; float: finite (real float32 shortest)
  - boolean; ISO date; UTC datetime with ≤6 fraction digits
  - selects: label values, multi in choice order
  - authorship: nullable lowercase UUIDs
  - Never round JS numbers into int64, numeric or microseconds.
  - Empty nullable values become NULL; checkbox null/empty becomes false.
- **D-117/D-122 datetimes**
  - Decode requires an offset.
  - Offset-free paste uses the effective viewing-user or fixed zone. DST
    gaps fail; overlaps choose the earlier instant.
  - Copy retains offset, microseconds and historical seconds.
  - Explicit UTC applies at the 0000/10000 local-year boundary.
  - Dates and instants are bounded to 0001..9999.
- **D-118/D-128 selects**
  - Unknown labels fail on write and are never auto-created.
  - Removed choices keep their stored labels on read (shown as unknown).
  - Label edits rewrite stored values by choice id in the field
    transaction.
- **Field metadata (D-123..D-130)**
  - Each field has `version`, `position`, `is_required`, `is_unique`,
    `default_json` (canonical wire) and `deleted_at`.
  - Physical columns are generated `c_` + ten lowercase base32 characters
    (`pg_column`) and are never exposed in DTOs.
  - System fields are `id/created_at/created_by/updated_at/updated_by`, with
    uiType equal to the column name, positions in the 1e9+ block, read-only
    values and isRequired true.
  - Soft-deleted fields keep their column and data with NOT NULL and user
    default dropped. Exclude them from query/rows I/O and ignore their ids
    in view configs.
  - Required/unique/default are physical constraints: NOT NULL, unique
    index and typed literal default. Row writes must map NOT NULL and unique
    violations to safe translated errors and must never leak constraint or
    column names.
  - Field rewrites do **not** touch `updated_at/updated_by`. Row writes in
    T1.15 must set them (doc 08 §9, `updated_by` = actor) and must set
    `created_by` on insert.
- **Schema DTO and versioning**
  - GET `/tables/{id}/schema` returns table (with `displayFieldId`), fields
    (`default`, `version`), relations (currently empty), views, schemaVersion
    and myLevel.
  - Every field and display mutation bumps `schema_version` exactly once,
    under a `meta.tables` NO KEY UPDATE row lock inside the D-080 locks.
  - Decide and record how row/query requests detect a schema change
    concurrent with field DDL. Options: a schemaVersion echo/header, a
    KEY SHARE on `meta.tables`, or both. Never read a column dropped or
    altered mid-request without a defined error.
- **`internal/ddl`** works on the caller's pgx.Tx only, uses typed
  allowlisted descriptors and has a three-second lock timeout. Physical DROP
  means purge, not soft delete. Keep old migrations unchanged.
- **Field routes:** `POST /tables/{id}/fields`, `PATCH`/`DELETE /fields/{id}`
  with If-Match field version (stale returns 409 `ERR_VERSION_CONFLICT`),
  and `PATCH /tables/{id}` `{displayFieldId}`. Field bodies use the 512 KiB
  exception (D-125); every other route keeps 4096 bytes. **Record an explicit
  bounded body decision** for bulk patch/insert (row count, cell count and
  bytes). Do not remove limits globally.

### Authorization / privacy / frontend invariants

- **Row levels (doc 06):** read requires effective read, while
  create/patch/delete require write (or owner). Admin has no data-access
  bypass. A hidden, missing or trashed table/view/row returns 404; a visible
  table with insufficient permission returns 403.
- **Locks:** mutations reauthorize uncached under the D-080/D-099 locks.
  Record any row-level locking or serialization before implementing it.
  Preserve D-081..D-087.
- **ACL cache:** LRU4096/TTL5s/process epoch. It is never a substitute for
  authorization, and committed grant/lifecycle changes invalidate it
  immediately.
- **User value resolution:** `created_by/updated_by` UUIDs are values. Do
  **not** reuse the owner-only sharing directory to resolve user names. Any
  user-name resolution for rows needs a recorded privacy/authorization
  decision first; returning UUIDs only is acceptable for T1.15.
- **Mutation requests:**
  - exact Origin and `X-PT-CSRF: 1`
  - bounded known-member JSON and no-store
  - ten-second deadlines and correlated redacted errors
  - forced password change returns 403 `ERR_PASSWORD_CHANGE_REQUIRED`;
    disabled or unauthenticated returns 401
  - translate codes/reasons, never server messages
- **Frontend state:** memory-only auth/nav/schema state guards stale
  responses. FieldPanel (lazy) replaces schema from authoritative responses.
- **i18n and bundle:**
  - Visible strings go in en and zh-CN with static keys.
  - CSP has no inline or eval relaxation.
  - Initial gzip must stay <600000 bytes (now 188707) with no initial grid
    imports.
  - Do not wire the synthetic grid into production routes. The production
    grid belongs to T1.16.

## Implementation and handoff (2026-10-26)

### Implementation

- Implemented `POST /views/{id}/query`, row GET/insert/single patch/bulk patch/
  delete, using the T1.15 contracts above. Query paging is bounded to 100 rows
  and offset 1,000,000; exact count defaults on but can be omitted. Sort is a
  single bound metadata field, `NULLS LAST` in either direction, then id
  ascending. View-config visibility/order follows D-132.
- Added structure-service metadata queries and generated sqlc bindings for
  stable view/table/schema reads. Row reads/writes bind all 12 writable codecs;
  reads encode all live fields and writes decode supplied fields. Physical
  typed defaults apply when omitted. Inserts/patches maintain system timestamps
  and actor UUIDs. Bulk requests are bounded, transactional and atomic.
- Reads and mutations use table schema locks so field DDL cannot change the
  physical columns during I/O. Mutations reauthorize uncached under the
  existing lock order. Safe errors cover required, unique, codec, lock timeout
  and schema serialization cases. Author UUIDs are returned as values only.
- Added protected HTTP routes with existing exact-Origin/CSRF/deadline/no-store
  middleware, request-body limits and strict known-member decoding. Added
  TypeScript DTOs and localized safe error codes; no production grid or initial
  grid import was added.
- Recorded D-132..D-137, including query/row bounds and semantics, atomic
  failure policy, schema locking, authorship/privacy and the Squirrel SQL
  builder and deterministic row-lock ordering. Squirrel v1.5.4 is the only new
  runtime dependency; the convention requires it for dynamic SQL. No
  migrations were added.
- Updated data-model, query, API, frontend, conventions, dev/test, progress and
  acceptance documentation. Created [T1.16 DataGrid prompt](T1.16.md) with the
  current codec/field/schema/query/row/permission/privacy/timezone/resource/
