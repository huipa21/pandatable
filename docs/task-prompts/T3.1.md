## Scope

- Implement the realtime hub: a dedicated PostgreSQL `LISTEN` connection, a shared `pg_notify` emission helper, and `/api/v1/ws` using the existing project conventions.
- Wire the helper into row, schema, view, navigation, and grant mutations. Preserve commit-then-notify semantics and keep payloads below PostgreSQL's notification limit; cap row IDs at 500 and send a bulk/reload event above that.
- Implement authenticated WS subscriptions with server-side table read-ACL checks, unsubscribe, ping/pong, heartbeat, event IDs, and suppression of the originating client's echoed events.
- Integrate the client store and reconnect flow: exponential backoff from 1 to 30 seconds; on reconnect resubscribe and reload the visible window rather than replaying missed events.
- Meet AT-601 (row create/update/delete propagation), AT-602 (same-cell LWW and remote-edit indicator), AT-603 (schema refresh), AT-605 (reconnect resync), and AT-107 (disabled/revoked session receives `session.revoked` within 5 seconds).
- Out of scope: presence behavior/UI, comments and notifications, row history, undo/redo, and event replay. Keep the protocol compatible with the message types reserved for those later tasks.

## Contracts to respect

- Follow the envelope and message types in `docs/10-collaboration.md` §1 and `docs/09-api.md` §3. Row update clients refetch visible affected rows in a batch and mark offscreen data stale.
- Keep each notification small; more than 500 row IDs becomes a bulk/reload signal. Notifications are delivered only after the originating transaction commits.
- Preserve per-cell last-write-wins behavior: PATCH contains only changed fields; a remote edit to the active cell shows who changed it, and saving the local value wins.
- Enforce authorization on the server for every subscription and deliver revocation to open sessions without waiting for another client request.
- Use the shared `events.Emit` hook already left by earlier mutation tasks; replace its no-op behavior and remove completed `TODO(T3.1)` hooks. Do not silently drop listener, hub, or websocket errors.
