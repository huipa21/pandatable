### Actual ACL/grants contract

- D-079/D-080 and doc 09: `GET /grants?resource=workspace:<uuid>` (also book/
  table), `PUT /grants` with `{resourceType,resourceId,principalType,principalId,
  level}`, `DELETE /grants/{id}`. Listing as well as mutation requires effective
  **owner of that scope**; non-owner visible/path-only -> 403, hidden/missing/
  trashed target/ancestor -> 404. Admin role is irrelevant.
- GET returns `{resource,effectiveLevel,items,inherited}`. Direct items include
  `inheritedLevel` (nullable, highest inherited level for the same principal);
  inherited ancestors are ordered workspace first. A grant contains id,
  resource/principal types/ids, level, grantedBy, createdAt and nullable
  `principal`: user `{name,username,status}` or group `{name,username:null,
  status:null}`. Render dangling principals honestly without leaking data.
- PUT is 201 created or 200 replaced/unchanged, returns
  `{grant,created,eventId}`. DELETE returns `{eventId}`. Principal missing ->
  404 `ERR_PRINCIPAL_NOT_FOUND`; disabled -> 409 `ERR_PRINCIPAL_DISABLED`.
  Malformed grant/resource references are 400 (unlike structure UUID paths,
  which use 404).
- Only-raise inheritance: lower direct grants are allowed but cannot restrict
  inherited access. Warn using the actual per-principal `inheritedLevel`;
  show direct and inherited sources distinctly. Do not suggest a lower direct
  grant removes an inherited owner level.
- Removing/downgrading an active direct workspace owner must leave another
  active **direct user** owner; group/disabled owners do not count.
  `ERR_LAST_OWNER` is 409. Book/table owners have no such protection. Disabled
  owners' existing grants may be removed. Disable itself can orphan a workspace.
- Resolver: one SQL lookup joins flat memberships and live-path grants; LRU4096,
  TTL5s and process epoch. Every committed grant/membership/role/status/resource
  lifecycle change (including uncertain commits) invalidates immediately.
  Mutations always reauthorize uncached inside the workspace-locked transaction.
- Lock protocol: workspace NO KEY UPDATE, book/table KEY SHARE, principal SHARE
  (one statement/lock); target-first hard deletion then polymorphic cleanup.
  Preserve principal/admin/last-owner locks D-081..D-087 and structure actor
  SHARE/three-second lock timeout D-099. No auth/SQL shortcuts.
- Doc 09's `/directory/users` and `/directory/groups` entries are planning,
  not proof they are implemented. Inspect actual routes. Non-admin owners must
  not call admin user/group APIs. Resolve and record a bounded, privacy-aware
  real picker contract if needed; do not ship SQL fixtures, hardcoded ids,
