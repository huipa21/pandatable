## Binding codec, schema, query and row contracts

- Writable batch-1 kinds: text, long_text, integer, decimal, float, checkbox,
  date, datetime, single_select, multi_select, email, url. The five system kinds
  are read-only. Reuse existing Go codecs and matching frontend FieldKind for
  validation, paste/copy, constraints, canonical options and aggregation
  capabilities. Unknown select labels fail writes; removed labels stay readable.
  Do not add a seed-only codec, validator or incompatible wire representation.
- Decode supplied row values and encode returned values with their field
  codecs. `codec.APIError` is a safe 400 `ERR_VALIDATION`; unknown stored metadata
  and unsupported scans are server errors.
- Canonical bigint values and positive row IDs are decimal strings, never JS
  numbers. Decimal values are fixed-scale strings (precision <=38, excess
  nonzero fraction rejected); small/int are numbers; floats finite and real
  float32-shortest; checkbox boolean; dates ISO; datetimes UTC instants with
  <=6 fractional digits; selects labels and multi-select choice order. Do not
  round numeric or microsecond values through JavaScript numbers.
- Datetime writes require an offset. Offset-free paste uses the effective
  viewer or fixed zone; DST gaps fail, overlaps choose the earlier instant.
  Copy preserves offset/microseconds/historical seconds. Explicit UTC applies
  when display zones cross local year 0000/10000; stored dates and instants stay
  in 0001..9999.
- Metadata carries field version/position/required/unique/canonical-wire
  default/deleted_at. Generated `c_` plus ten lowercase base32 physical names
  never appear in DTOs. System fields id/created_at/created_by/updated_at/
  updated_by are read-only in the 1e9+ position block. Deleted fields retain
  physical data but are absent from row/query I/O and ignored in views.
  Constraints/defaults are physical; field rewrites preserve row authorship.
- `GET /tables/{id}/schema` returns displayFieldId, fields/default/version,
  empty relations, visible views, schemaVersion and myLevel. Every field/display
  mutation increments schema version exactly once under metadata locks.
- `POST /views/{id}/query` accepts offset 0..1,000,000, limit default 100
  (1..100), optional single typed sort, includeCount default true and optional
  D-138 transient ordered fieldIds. It returns
  `{rows:[{id,fields}],fieldIds,total,schemaVersion}`. Count is null only when
  disabled. Sort has NULLS LAST in both directions, then row ID ascending.
  Configured live fields retain order; duplicate/unknown/deleted IDs are ignored;
  omitted user fields append by metadata order, system fields hidden unless
  explicitly visible. Configured sort applies unless overridden. fieldIds is
  not persisted and changes no authorization.
- Existing row routes: GET `/tables/{id}/rows/{rowId}` returns full `{id,fields}`;
  POST `/tables/{id}/rows` `{rows:[{fields}]}`; PATCH single row `{fields}`
  returns `{row,eventId}`; PATCH bulk `{rows:[{id,fields}]}`; DELETE bulk
  `{ids}` returns snapshots. Bulk insert/patch <=1000 rows/5000 supplied cells,
  512 KiB body; delete <=1000 IDs/64 KiB. Other requests remain 4096 bytes.
  Do not truncate, split an atomic operation or change these limits. Invalid
  GET row IDs return neutral 404, not 400. Missing required row values return
  safe 400 `ERR_REQUIRED_FIELD`; unique conflicts are 409.
- Bulk operations are atomic. Patches lock rows FOR UPDATE; later successful
  lock holder wins, with no row version. Bulk patch locks ascending numeric IDs
  but responds in request order. Inserts omit unspecified values for physical
  defaults; one transaction timestamp initializes creation/update times and both
  authorship UUIDs. Patches preserve creation values. Authors remain nullable
  lowercase UUIDs, never names or sharing-directory lookups.
- Read requires effective table read; writes require write/owner. Admin has no
  data bypass. Hidden/missing/trashed resources are 404; visible insufficient
  access is 403. Reauthorize writes uncached under D-080/D-099 locks. Table
  FOR SHARE protects row/query snapshots against field DDL FOR NO KEY UPDATE.
  Three-second lock timeout => ERR_DDL_LOCK_TIMEOUT; repeatable-read
  serialization => ERR_SCHEMA_CHANGED.
- Required/unique errors stay sanitized; never expose physical names, values,
  constraints or PG text. Mutations need exact Origin, X-PT-CSRF:1, bounded
  known-member JSON, no-store and ten-second deadlines. Forced-password is 403;
  disabled/unauthenticated is 401. Preserve redaction/correlation IDs.
- Dynamic data SQL uses Squirrel, validated metadata and pgx.Identifier; values
  are parameters. Static metadata uses sqlc. No client name/type/options/
  expression/identifier interpolation. Use internal/testdb.Suite for PG tests.
