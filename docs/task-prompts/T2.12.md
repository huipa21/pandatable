## Contracts to respect

- Only an owner may make schema changes (D-022). Dry-run reports `{total, convertible, failing, samples:[{id, value}]}` for non-null values; show representative failing samples.
- Abort must leave data and schema unchanged. Conversion and its `USING` expression run atomically; failing values become NULL only when that option is selected. Record one `type_change` history event per table, not one per row.
- Use `pg_input_is_valid` where supported and a type-specific converter for specialized pairs (including multi-select to single-select and checkbox to text). Do not build SQL types or expressions from unvalidated user input.
- Re-type-check dependent formulas/lookups/rollups after conversion. Persist errors in `options.error` and render `#ERROR`; they must not prevent conversion.
- Select choices are stored by label but identified by id. Renames rewrite values/default atomically; filters referencing the renamed choice must continue matching it. Preserve D-118/D-128 behavior for removed choices and orphan labels.
- Keep user-visible UI text localized in both `en` and `zh-CN`; follow the existing error format and frontend patterns.
