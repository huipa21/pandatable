## Scope

- Admin API (role=admin only): list/search users (`q`, status, pagination
  `{items,total}`, limit <= 500), create (`username, email?, displayName, role,
  password` with must_change_password=true), PATCH (displayName, email, role,
  status), reset password (forced change, revoke all sessions), disable/enable
  (revoke sessions, serialize on the user row, invalidate ACL cache). Disabled
  users cannot log in and their data/authorship remains.
- Protect against locking out the instance: define and test last-active-admin
  rules for role change/disable. Reject duplicate/ambiguous usernames and emails.
- Admin UI: admin-only menu entry and `/admin/users` route (list/search/create/
  edit/role/disable/reset password), plus the forced `/change-password` flow if
  chosen; non-admins see no Admin menu and `/admin/*` redirects (AT-108).
  Desktop and mobile (< 768 px) layouts; English and Simplified Chinese.

  (T1.8), ownership transfer/hard delete (M3), SSO, API tokens or self-
