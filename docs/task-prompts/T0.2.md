# Task prompt - T0.2 Config & CLI

Implement **T0.2 - Config & CLI** for PandaTable, starting from the committed
T0.1 scaffold. Work from the repository root on Windows; support Linux too.

## Read first

Read `AGENTS.md`, `docs/README.md`, `docs/02-architecture.md`,
`docs/13-deployment.md` section 4, `docs/conventions.md`,
`docs/decisions.md`, the T0.2 row in `docs/04-implementation-plan.md`, and
`docs/progress.md`. Inspect `cmd/pandatable/main.go` and `tools/ptdev` locally.
Mark T0.2 started before coding. Preserve unrelated worktree changes.

## Scope

- Add `internal/config`: environment + flag configuration for the app settings
  in deployment section 4. Flags override environment, which overrides defaults.
  Validate required values and malformed numeric, URL, log-level and CIDR inputs
  with actionable errors; never expose credentials in errors or logs.
- Use the documented defaults: `PT_DATA_DIR=/data`, `PT_LISTEN=:8080`,
  `PT_DB_MAX_CONNS=20`, `PT_LOG_LEVEL=info`, `PT_DB_CONNECT_RETRIES=30`.
  Required connection/public URL settings and trusted-proxy defaults must follow
  the deployment/security docs. Ask if a security-sensitive default is unclear.
- Implement CLI routing for `serve` and `migrate`, plus explicit stubs for
  `restore`, `doctor`, and `reset-admin-password`. Keep `version` and the existing
  linker-injected `main.version`. Database/migration execution is T0.3; HTTP is
  T0.4: validate config and report these implementation boundaries honestly.
- Configure `log/slog` JSON output to stdout, honoring the configured level.
- Prefer the standard library and current exit-code conventions (0/1/2).
  Do not add third-party dependencies without a concrete need and recorded choice.
- Add focused unit tests for precedence, defaults, invalid config, command
  parsing, help/version without database configuration, and secret redaction.
- Do not create an HTTP server, DB pool, migrations, frontend or deploy files.

## Verification and wrap-up

- Run focused unit tests first, then `go run ./tools/ptdev check`; keep existing
  ptdev tests green. If the engine is unavailable, report the actual error and
  run `test --no-db`, lint and build without claiming a full gate pass.
- Smoke-test CLI version/help and malformed arguments in PowerShell and Git Bash.
- Update progress and add decision entries for any new non-trivial choice. Keep
  AT-006 pending until its Linux/Docker and integration-harness checks pass in T0.7.
- Commit the task as `feat(cli): config and command routing [T0.2]`.
- Finish with a concise implementation/verification/deviation report and a
  ready-to-use T0.3 prompt in `docs/task-prompts/T0.3.md`.
