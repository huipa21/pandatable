## Scope

- Implement the Form view builder over the versioned view config: title/description, selected fields, custom labels/help, required flags, and `afterSubmit` behavior as documented in 08 §1.
- Implement authenticated `POST /views/{id}/form-submit` to validate the configured form and submitted values, then create one row through the existing safe row/codec path.
- Render the configured form for authorized table users, disable submission for read-only users, and make the builder and submission flow usable at mobile widths.
- Add focused API, frontend, and production-browser coverage for AT-511, including persistence/reload and validation/error states.

Out of scope: public/anonymous forms or share links, new field kinds, general view-management changes (T2.10), grid/card row creation redesign, and unrelated filter/sort/group/highlight features.

## Contracts to respect

- Forms are logged-in Form views only; D-030 explicitly excludes public forms. The existing view ACL applies: effective `write` or `owner` may submit; `read` may view but not submit. Enforce this server-side, with normal hidden-resource 404 and insufficient-level 403 behavior; admin role is not a data-access bypass.
- Persist form settings in `config.form` using the existing `PATCH /views/{id}` merge and `If-Match` version contract (D-178). Do not clobber other view config. Respect personal/shared visibility and locked-view edit rules; use existing supported Form view type rather than adding a new view lifecycle.
- Validate that configured field IDs are unique, live, and belong to the table. Reject malformed or stale submissions safely. Enforce form-required fields on the server as well as native/UI required state; retain schema-level constraints and codec validation. Do not accept system/computed/read-only fields as writable input.
- Create exactly one row atomically through existing row mutation semantics, respecting request limits, database defaults for omitted values, ACL, and standard sanitized API errors. Do not expose physical identifiers or bypass field codecs.
- Keep all visible text localized in `en` and `zh-CN`; support keyboard/touch use, dark mode, and a 390 px viewport. Do not imply that read-only users can submit.
