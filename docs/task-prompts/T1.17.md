### Accepted codecs, field, schema, query and row contracts

- Batch-1 writable field kinds are `text`, `long_text`, `integer`, `decimal`,
  `float`, `checkbox`, `date`, `datetime`, `single_select`, `multi_select`,
  `email`, and `url`. Five system kinds are read-only. Bind the existing Go
  codec and matching frontend `FieldKind`; do not add a parallel validator.
  Codec read/write, paste, format, constraints, aggregation and canonical
  options are authoritative. Unknown select labels fail writes; removed labels
  remain readable.
- Decode every supplied row value with its field codec and encode all returned
  values with that codec. `codec.APIError` is a safe 400 `ERR_VALIDATION`;
  unknown stored metadata/unsupported scans are server errors.
- Wire precision is exact: bigint row IDs and values are canonical decimal
  strings; decimal values are fixed-scale strings (precision <=38, excess
  nonzero fraction rejected); small/int are numbers; floats are finite and
  `real` uses float32-shortest; booleans are booleans; dates are ISO dates;
  datetimes are UTC instants with up to six fractional digits; selects are
  labels and multi-selects follow choice order. Never round JS numbers into
  bigint, numeric or microseconds.
- Datetime input writes require an offset. Offset-free paste uses the effective
  viewing-user or fixed zone; DST gaps fail and overlaps choose the earlier
  instant. Copy preserves offset, microseconds and historical seconds.
  Explicit UTC applies at local years 0000/10000 boundaries; stored dates and
  instants are bounded to 0001..9999.
- Field metadata carries version, position, required/unique flags,
  canonical-wire `default_json`, and `deleted_at`. Generated physical names
  are `c_` plus ten lowercase base32 characters and never appear in DTOs.
  System fields are `id`, `created_at`, `created_by`, `updated_at`, and
  `updated_by`, read-only/required in the 1e9+ position block. Deleted fields
  retain physical columns/data but are excluded from row/query I/O and ignored
  in view config. Required/unique/default are physical constraints; field
  rewrites do not change authorship.
- `GET /tables/{id}/schema` returns table `displayFieldId`, fields/default/
  version, empty relations, views, `schemaVersion`, and `myLevel`. Field and
  display mutations increment schema version exactly once under the metadata
  lock.
- Query route is `POST /views/{id}/query`. Request supports bounded
  `offset` (0..1,000,000), `limit` (default 100, 1..100), optional typed sort,
  `includeCount` (default true), and the D-138 transient `fieldIds` override.
  Response is `{rows:[{id,fields}],fieldIds,total,schemaVersion}`. Count may
  be `null` only when disabled. A single typed sort uses `NULLS LAST` in both
  directions then row ID ascending. Configured live fields preserve order;
  duplicate/unknown/deleted IDs are ignored, omitted live user fields append
  in metadata order, and system fields are hidden unless explicitly visible.
  Configured sort applies absent an override. D-138 `fieldIds` is ordered,
  validated against live metadata, may include explicitly requested system
  fields, is not persisted, and does not alter authorization.
- Row routes: `GET /tables/{id}/rows/{rowId}`; bulk create
  `POST /tables/{id}/rows` `{rows:[{fields}]}`; single patch
  `PATCH /tables/{id}/rows/{rowId}` `{fields}`; bulk patch
  `PATCH /tables/{id}/rows` `{rows:[{id,fields}]}`; bulk delete
  `DELETE /tables/{id}/rows` `{ids}` returning snapshots. IDs are canonical
  positive bigint decimal strings. Bulk insert/patch: <=1,000 rows, <=5,000
  supplied cells, 512 KiB body; bulk delete: <=1,000 IDs, 64 KiB. Other
  requests remain 4,096 bytes. Bulk operations are atomic. Patches lock rows
  `FOR UPDATE`; successful concurrent patches serialize and later lock holder
  wins. Bulk patches lock IDs in ascending numeric order, preserving request
  response order.
- Inserts omit unspecified columns so typed physical defaults apply; they set
  `created_at`/`updated_at` to one transaction timestamp and both authorship
  values to the actor. Patches set `updated_at`/`updated_by`, preserving
  creation values. Author UUIDs are nullable lowercase UUIDs only; do not
  resolve names or use the owner-only sharing directory. No row version exists.
- Read requires effective table read; writes require effective write or owner.
  Admin role does not bypass data access. Hidden/missing/trashed resources are
  404; visible insufficient access is 403. Writes reauthorize uncached under
  D-080/D-099 locks. Table `FOR SHARE` protects row/query schema snapshots
  against field DDL's `FOR NO KEY UPDATE`; 3-second DDL lock timeout is safe
  `ERR_DDL_LOCK_TIMEOUT`; repeatable-read serialization is
  `ERR_SCHEMA_CHANGED`.
- Required and unique violations map to safe translated `ERR_REQUIRED_FIELD`
  and `ERR_UNIQUE_CONFLICT`; never expose PG column, constraint, value or
  server text. Mutation requests require exact Origin, `X-PT-CSRF: 1`,
  bounded known-member JSON, no-store, and ten-second deadlines. Forced
  password change is 403; disabled/unauthenticated is 401. Preserve
  correlation and redacted errors.
- Dynamic data SQL uses Squirrel; physical identifiers come only from
  validated metadata and `pgx.Identifier`; values are parameters. Static
  metadata uses sqlc. Do not interpolate client names, PGType, options,
  expressions or physical identifiers.

## Implementation and handoff (2026-10-27)

### Implementation

- Implemented clipboard copy/cut/paste and fill-down on the production
  `DataGrid.vue`, preserving the separate synthetic spike. Clipboard values
  flow through the bound field codec's `formatCopy`/`parsePaste`; valid cells
  stay typed/exact and high-precision wire values are not coerced through JS
  numbers. Paste reports invalid row/field cells, submits valid edits to
  existing rows in one bounded bulk PATCH, and asks before appending rows.
  Oversize data is rejected rather than silently truncated. Ctrl+D and the
  vertical fill handle extend only down.
- Reworked RevoGrid source updates to replace the reactive source rather than
  mutate the engine store directly; added a Vue template cell host using
  `useTemplates()` and runtime-declared editor props. The editor resolves its
  field from the current column instead of a stale captured field. Remote row
  events/ranges are mapped by row ID or bounded virtual-window anchors because
  RevoGrid event row indexes can be viewport-relative or temporarily -1.
  `RemoteRowsWindow.indexOfRow()` only scans the active bounded cache.
- Added codec/component tests, virtual-window lookup/eviction coverage,
  production-image AT-306..309 browser assertions and matching en/zh-CN
  strings. Fixed the existing mobile fallback notice CSS order so it is
  visible below 768 px; no production grid or T1.17 controls mount there.
- Recorded the production-grid clipboard and bounded RevoGrid index policy in
  D-139. No dependencies, API routes, migration, or schema changes.
