## Scope

- Implement lookup and rollup computed fields using existing relation metadata:
  correlated subqueries for 1:1, 1:N and M:N, with M:N traversing the junction.
- Provide field configuration UI and evaluate the configured target field and
  aggregation at query time; lookups return arrays, rollups return scalars.
- Support rollup `count`, `sum`, `avg`, `min`, `max`, `earliest`, `latest` and
  `concat`; verify value updates when related rows change.
- Enforce cross-table masking: without read access to the target table, mask
  lookup/rollup values and do not expose them for filtering (AT-411).
- Pass AT-407, AT-408 and AT-411 with real PostgreSQL and browser coverage.

Out of scope: formula language/editor (T2.5), general filter/sort implementation
(T2.6), unrelated relation changes, and computed-field persistence or materialized
values.

## Contracts to respect

- Per D-018 and doc 08 §8, compute values at query time; do not persist or add
  generated columns. Compile expressions from validated metadata, not client SQL
  or identifiers; use correlated subqueries, including the relation junction
  for M:N.
- Respect relation direction and cardinality. Lookup returns the target field's
  values as a JSON array with target-type filter semantics; rollup is a scalar
  using the selected aggregate. Handle empty relations and nullable values
  consistently with the existing query/codec contracts.
- Apply target-table read permission before returning computed values. Follow
  D-044 and doc 06 §6: unauthorized values are masked, not merely hidden in the
  UI, and cannot be used to infer target data through filtering. Preserve
  permitted link-cell display behavior.
- Keep table/field configuration owner-authorized and localized in both `en`
  and `zh-CN`. Surface validation/query failures through existing API error
  conventions.
