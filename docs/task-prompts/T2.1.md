## Contracts to respect

- PG types exactly as 07 §1. Physical changes only through `internal/ddl` typed
  descriptors inside the caller transaction; no raw SQL strings from options.
- Strict options (unknown keys fail), exact wire values, no JS-number rounding:
  currency/percent are fixed-scale decimal strings like `decimal`; `int_array`
  items and `autonumber` are bigint decimal strings; `uuid`/`user` lowercase.
- Currency: new field defaults to the admin `default_currency` setting at
  creation and stores the ISO 4217 code in options; later setting changes do
  not alter existing fields (AT-326). Display via `Intl.NumberFormat`.
- Unique eligibility per 07 §4; `autonumber` is read-only like system kinds.
- Every new user-visible string in `en` and `zh-CN`; editors lazy-loaded;
  initial shell stays < 600000 bytes gzip; 100-row pages, <= 300 cached rows.
- No new dependency (use `net/netip`, `encoding/json`, existing codecs).

## Decisions to record (one D-xxx each; confirm with the user if unsure)

1. **DDL additions:** CHECK `0..max` (rating), FK → `meta.users(id) ON DELETE
   SET NULL` (user), per-field sequence `s_<short>` with `DEFAULT nextval`
   (autonumber; existing rows numbered in `id` order at creation; sequence
   dropped only on purge). Keep them allowlisted typed operations.
2. **Wire formats/bounds:** `time` `HH:MM:SS[.ffffff]`; `duration` — recommend
   ISO 8601 `PT#H#M#S` without year/month/day parts; `json` max serialized
   size (recommend 64 KiB) and canonical re-encoding; array max items/length;
   `phone` loose pattern and max length; `rating` `max` 1..10.
3. **User picker:** D-109's directory is owner-only, but a table **writer**
   must pick users and readers must see names. Recommend a table-scoped,
   write-access route returning `{id,name,username}` of active users (same
   search bounds as D-109) plus a read-access label resolver for stored IDs;
   no email/role/status exposure. Deleted users render as a localized unknown.
