## Contracts to respect

- Store files only under `PT_DATA_DIR/files/<yyyy>/<mm>/<uuid>`; persist metadata in `meta.attachments` and cell values as the documented `{id,name,mime,size,thumb}` array. Preserve the existing table/field metadata constraints (D-069).
- Enforce `uploadMaxMb` as MiB (default 20, range 1..100) per file, including while consuming multipart bodies; return a localized rejection for over-limit files. Never trust a client MIME type or filename as a path. Sniff MIME; only PNG/JPEG/GIF/WebP are inline and thumbnailed at no more than 256 px. Reject images exceeding persisted `imageMaxMegapixels` (default 16, range 1..16) before full decode.
- `accept` is an optional comma-separated list of up to 20 exact MIME types or top-level wildcards; empty accepts all sniffed types and `*/*` is invalid. `maxFiles` defaults to 10 and is bounded 1..20 (D-163..D-166).
- Tightened field options must not make previously stored attachment values unreadable (D-168).
- Upload requires table write access; serving requires table read access and returns 404 when access is absent. Serve as attachment except safe image types, with `X-Content-Type-Options: nosniff` (D-026; 13 §9).
- Handle partial failures so DB metadata and filesystem contents do not leave avoidable orphan files. Honor the field's MIME allowlist and file-count limit. If a necessary default, bound, or security behavior is not specified, do not silently invent it: record a new D-xxx and confirm with the user.
- Add every user-visible string to both `en` and `zh-CN`; keep existing shell-size and row/page cache limits.
