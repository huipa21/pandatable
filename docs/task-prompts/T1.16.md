### Accepted T1.15 backend contract

- The server supports the 12 writable batch-1 kinds: `text`, `long_text`,
  `integer`, `decimal`, `float`, `checkbox`, `date`, `datetime`,
  `single_select`, `multi_select`, `email`, and `url`; five system kinds are
  read-only. Go codecs bind canonical options, constraints, read/write, paste,
  format and aggregation behavior. Do not create a parallel validator.
- Decode every supplied row value with its field codec; encode every returned
  value with the codec. `codec.APIError` is 400 `ERR_VALIDATION` with safe
  reason/option; unknown stored metadata or unsupported scans are server
  errors. Unknown select labels fail on write; removed labels remain readable.
- Wire values: bigint row IDs and bigint values are canonical decimal strings;
  decimals are fixed-scale strings (precision at most 38; excess nonzero
  fraction fails); small/int values are numbers; floats are finite and real
  uses float32-shortest; booleans are booleans; dates are ISO dates; datetimes
  are UTC instants with at most six fractional digits; selects are labels and
  multi-select values follow choice order. Never round JS numbers into int64,
  numeric or microseconds.
- Datetime writes require an offset. Offset-free paste uses the effective
  viewing-user or fixed zone; DST gaps fail and overlaps choose the earlier
  instant. Copy preserves offset, microseconds and historical seconds.
  Explicit UTC applies at local years 0000/10000 boundaries; dates and instants
  are bounded to 0001..9999.
- Each metadata field has version, position, required/unique flags,
  canonical-wire `default_json`, and `deleted_at`. Physical names are generated
  `c_` plus ten lowercase base32 characters and never appear in DTOs. The
  system fields are `id`, `created_at`, `created_by`, `updated_at`, and
  `updated_by`, read-only/required in the 1e9+ position block. Deleted fields
  retain physical data/columns, are excluded from row/query I/O, and are
  ignored in view config. Required/unique/default are physical constraints;
  field rewrites do not change row authorship.
- Schema is returned by `GET /tables/{id}/schema` with table
  `displayFieldId`, fields/default/version, empty relations, views,
  `schemaVersion`, and `myLevel`. Field/display mutations increment
  `schema_version` exactly once while holding the table metadata lock.
- Query route is `POST /views/{id}/query`:
  `{offset?,limit?,sort?:{fieldId,direction},includeCount?}` ->
  `{rows:[{id,fields}],fieldIds,total,schemaVersion}`. Offset is
  0..1,000,000; limit defaults to 100 and is 1..100; exact count defaults on,
  and `includeCount:false` returns `total:null`. A single typed sort column
  uses `NULLS LAST` both ways, then row id ascending. Visible configured live
  fields preserve order; duplicates/unknown/deleted IDs are ignored; omitted
  live user fields append in metadata order; system fields are hidden unless
  explicitly visible. Configured sort is used absent an override.
- Row endpoints:
  - `GET /tables/{id}/rows/{rowId}` returns `{id,fields}` for all live fields.
  - `POST /tables/{id}/rows` accepts `{rows:[{fields:{fieldId:value}}]}`.
  - `PATCH /tables/{id}/rows/{rowId}` accepts `{fields}`.
  - `PATCH /tables/{id}/rows` accepts `{rows:[{id,fields}]}`.
  - `DELETE /tables/{id}/rows` accepts `{ids:[...]}` and returns snapshots.
  Row IDs are canonical positive bigint decimal strings. Bulk insert/patch are
  limited to 1,000 rows and 5,000 supplied cells, with 512 KiB request bodies;
  bulk delete is limited to 1,000 IDs and 64 KiB. Other requests retain 4,096
  bytes. Bulk operations are atomic. There is no row version: patch locks rows
  `FOR UPDATE`; concurrent successful patches serialize, later lock holder
  wins. Bulk patches lock rows in ascending numeric ID order to avoid
  overlapping-batch deadlocks and preserve request order in responses.
- Inserts omit unspecified columns so typed physical defaults apply. Inserts
  set `created_at` and `updated_at` to one transaction timestamp and both
  authorship values to the actor; patches set `updated_at`/`updated_by` and
  preserve creation values. `created_by`/`updated_by` are nullable lowercase
  UUID values only; do not resolve names or reuse the owner-only sharing
  directory.
- Read requires effective table read. Create/patch/delete require effective
  write or owner. Admin role has no data-access bypass. Hidden/missing/trashed
  table/view/row is 404; visible resources with insufficient access are 403.
  Writes reauthorize uncached under the D-080/D-099 locks. A table `FOR SHARE`
  protects row/query schema snapshots against field DDL's `FOR NO KEY UPDATE`.
  Three-second lock timeout maps to sanitized `ERR_DDL_LOCK_TIMEOUT`;
  repeatable-read schema serialization maps to `ERR_SCHEMA_CHANGED`.
- NOT NULL and unique violations map to safe translated
  `ERR_REQUIRED_FIELD` / `ERR_UNIQUE_CONFLICT`; never expose PG column,
  constraint, value, or server text. Mutation requests require exact Origin,
  `X-PT-CSRF: 1`, bounded known-member JSON, no-store, and ten-second
  deadlines. Forced password change returns 403; disabled/unauthenticated
  returns 401. Preserve correlation and redacted errors.
- Dynamic data SQL uses Squirrel. Physical identifiers come only from
  validated metadata and `pgx.Identifier`; values are parameters. Static meta
  queries use sqlc. Do not interpolate client names, PGType, options,
  expressions or physical names.

### Frontend and acceptance boundaries

- The real route is `/t/:tableId/v/:viewId`; FieldPanel is already lazy and
  replaces schema from authoritative responses. Add the production DataGrid
  there, not through a synthetic production route. Keep grid/editor imports
  out of the initial bundle; initial gzip must remain below 600,000 bytes
  (T1.15 measured 188,853 bytes).
- Use API types and helpers in `web/src/api`, memory-only auth/navigation/
  schema state, stale-response guards, static i18n keys in both `en` and
  `zh-CN`, and existing error translation. No hard-coded visible strings.
  Never show a success-shaped fallback after a failed request.
- Full AT-301 requires creating each of the 12 kinds in the real grid, entering
  values, saving and reloading, with expected PostgreSQL types. Full AT-302
  requires visible cell validation and no persistence on invalid integer and
  email values. Full AT-303 requires populated-table required/unique setup and
  default values on new rows. Full AT-304 requires Fields-menu system columns
  and correct `updated_by` after editing. None is full from unit, codec, SQL,
  or API fixtures alone.
- Full AT-312 requires the real 200k-row grid to first-paint under 1.5 s and
  load middle pages under 300 ms, within the documented test environment.
  T1.15 measured a Suite-owned PG18 API fixture (seed 579.6752 ms, page at
  offset 100,000 26.1817 ms, page+count 20.394 ms); this is API-only evidence,
  not NFR-2 certification. NFR-1 is also not certified (last measured desktop
  post-auth RSS was 232,652,800 bytes).
- AT-204..207 still need real rows/editors/shared views; AT-203 restore is M3.
  AT-111/322 await T2.2 uploads; AT-117 awaits real datetime/filter UI; AT-804
  awaits T2.6. Preserve passed M1 evidence; do not claim dependent acceptance
  early. Observe `docs/01-requirements.md` Out of Scope: no integrations,
  external DB connectors, SSO, enterprise audit, sync, self-registration,
  public sharing, or API tokens.
- Browser budgets stay unchanged: D-112 scenario 150 seconds/global 360
  seconds, one worker, zero retries, unchanged five-second assertions and
  budgets. Pre-register intentional HTTP failures with `expectHTTPFailure`.
  Preserve desktop nav drag idle/draggable wait. Test both locales/themes.
- PG18 integration tests use `internal/testdb.Suite`, explicit DSN and
  `PT_TEST_DATABASE_REQUIRED=1`; uncached runs use `-count=1`. Report
  default-parallel Suite DROP cleanup failures separately from scoped
  `GOFLAGS=-p=1`; never relax deadlines/assertions. No hosted CI.
- Resources: host target is 2 vCPU/4 GB; do not add heavy dependencies.
  Inspect Podman VM, `pt-dev-db`, and worktree before work; restore runtime
  state afterward. Preserve `pt-dev-pgdata`, release images, Caddy and unrelated
  volumes. E2E may own only a uniquely named `pt-e2e-*` stack; no broad prune,
  reset or hosted CI.
