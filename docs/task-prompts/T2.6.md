## Scope

- Implement server-side filter-tree validation and parameterized SQL
  compilation for the documented operators, intersecting each field's
  declared `FilterOps` with the bound field type. Reject malformed trees,
  unsupported operations, invalid values and excessive depth.
- Support stored fields and query-time lookup, rollup and formula expressions;
  preserve computed-field permission masking and formula dependency rules.
- Evaluate relative date/time values in the requesting user's timezone and
  escape `%` and `_` in case-insensitive text matching.
- Support the documented JSON key/path predicates, inet/CIDR containment and
  link-count comparisons; D-173 records their wire shapes.
- Add a localized filter builder with type-aware operators, nested AND/OR
  groups up to depth 3, and real browser coverage for AT-501, AT-502 and the
  filter portion of AT-410.

Out of scope: multi-sort compilation/UI (T2.7), view-management or persisted
filter editing (T2.10), grouping/highlighting, and changes to computed-field
configuration or expression semantics.

## Contracts to respect

- Per docs 08 §§1–2, use the documented tree/operators and bind all values;
  resolve identifiers only from validated live metadata. Do not infer
  capabilities from raw PostgreSQL types. Preserve string precision for
  bigint/decimal wire values and honor nullable/empty semantics.
- Relative temporal operators use the requesting user's zone (D-049), with
  database sessions in UTC. Text matching is case-insensitive and treats
  `%`/`_` as literals.
- Compile formulas from their validated, stable-ID AST (D-018, D-172).
  Filtering computed fields must not bypass cross-table masking (D-044,
  D-171); do not offer or execute a lookup/rollup filter when target-table
  read access is missing.
- Keep query filtering transient; do not broaden T1.21's column-only
  `PATCH /views/{id}` contract or add view persistence. Follow existing API
  errors and localize all user-visible strings in both `en` and `zh-CN`.
- AT-410 also requires sorting formula and rollup fields. Verify whether the
  existing sort path supports this; implement only the filter portion here,
  coordinate any missing sort support with T2.7, and do not mark AT-410 fully
  passed until both behaviors have evidence.
