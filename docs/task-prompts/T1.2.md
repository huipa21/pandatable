## Scope

- Implement argon2id hashing/verification (m=64 MiB, t=1, p=2, tuned for
  2 vCPU). Use secure random salts, safe PHC parsing/parameter bounds, constant-
  time comparison and explicit errors. Bound expensive work against the
  2-vCPU/4-GB host; do not introduce a heavy auth framework.
- Implement random server-side session tokens, storing only SHA-256 hashes
  in `meta.sessions`; create/validate/slide/revoke. Idle timeout is 7 days,
  absolute timeout 30 days (deployment section 9). Reuse created_at,
  last_seen_at and expires_at; sliding must not extend absolute lifetime or
  recreate a concurrently revoked session. Disabled/expired sessions have no
  access. Never log tokens/passwords/hashes or expose them in DTOs.
- Add documented login by username **or email**, logout, `/auth/me`,
  change-password and profile preferences (display name, locale, theme,
  timezone). Validate IANA timezones against PostgreSQL's timezone catalog;
  NULL uses the app default Asia/Shanghai, DB storage/sessions remain UTC.
  Preserve typed API errors, hidden sensitive fields and mustChangePassword
  behavior without inventing admin/reset/setup services.
- Enforce login rate limits: 10/min/IP; five failed attempts cause a one-minute
  per-account lock, including rejection of a correct password during the lock.
  Username/email aliases must not bypass the same account limit. Derive client
  IP only through configured trusted proxies; an empty list trusts none.
- Session cookie is HttpOnly, Secure and SameSite=Lax. Mutating requests require
  `X-PT-CSRF: 1` **and** an Origin matching `PT_BASE_URL`; neither replaces the
  other. Do not weaken CSP or trust arbitrary forwarded headers. Handle local
  HTTP development/testing explicitly and document any necessary policy choice.
- No self-registration, JWT/API tokens, SSO, external providers, setup-token
  flow (T1.3), ACL/grants (T1.4), admin services or unrelated grid/query work.
  Do not seed real accounts or add test-only production auth endpoints. Where
  linked acceptance needs browser UI, resolve its scope honestly before claiming
  completion; all frontend user-visible text must use both locales.
- Preserve applied migrations. Any necessary schema change must be a new
  forward migration with owned rollback/upgrade tests, never an edit to 0001/0002.
  Prefer existing helpers and static typed queries; justify new lightweight
  dependencies. Do not relax build-context allowlists or resource constraints.
