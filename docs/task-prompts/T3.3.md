## Scope

- Implement row comments in the existing row modal, including API, UI, and comment counts.
- Add @mention autocomplete limited to users who can read the table; render mentions as links.
- Persist mention notifications, push them over the existing WebSocket, and provide a bell with unread count that opens the correct row and comment.
- Meet AT-606: Alice comments “@bob please check” on a row; Bob receives a live bell notification, and clicking it opens that row modal at the comment. The mention list must not offer users without table access.
- Out of scope: email notifications (T5.2), new realtime infrastructure, and unrelated collaboration features.

## Contracts to respect

- Reuse the existing `meta.comments` and `meta.notifications` schema; inspect the migrations and current services before making schema changes.
- Preserve the comments/notification access rules and transaction boundaries. A mention notification must only reach an eligible recipient.
- Use the existing realtime publication and event-ID conventions (D-183); do not introduce an event log or another WebSocket channel.
- Authors may edit/delete their comments; table owners may delete any comment. Comments remain associated with a soft-deleted row until its table is purged.
- All new user-visible frontend text needs `en` and `zh-CN` i18n keys.
