## Binding codec, schema, query and row contracts

- Writable batch-1 kinds: text, long_text, integer, decimal, float, checkbox,
  date, datetime, single_select, multi_select, email, url. The five system
  kinds are read-only. Reuse existing Go codecs and matching frontend FieldKind;
  validation, paste/copy, constraints, canonical options and aggregation
  capabilities remain authoritative. Unknown select labels fail writes;
  removed labels remain readable. Do not add a parallel validator.
- Decode every supplied row value with its field codec; encode every returned
  value with that codec. `codec.APIError` is a safe 400 `ERR_VALIDATION`;
  unknown stored metadata/unsupported scans are server errors.
- Canonical bigint values and positive row IDs are decimal strings, never JS
  numbers. Decimal values are fixed-scale strings (precision <=38, excess
  nonzero fraction rejected); small/int are numbers; floats finite and real
  float32-shortest; checkbox boolean; dates ISO; datetimes UTC instants with
  up to six fractional digits; selects labels and multi-select choice order.
  Never round numeric or microsecond values through JavaScript numbers.
- Datetime writes require an offset. Offset-free paste uses the effective
  viewing-user or fixed zone; DST gaps fail, overlaps choose the earlier
  instant. Copy preserves offset/microseconds/historical seconds. Explicit
  UTC is used when display zones cross local year 0000/10000; stored dates
  and instants stay in 0001..9999.
- Metadata carries field version/position/required/unique/canonical-wire
  default/deleted_at. Generated `c_` plus ten lowercase base32 physical names
  never appear in DTOs. System fields id/created_at/created_by/updated_at/
  updated_by are read-only/required in the 1e9+ position block. Deleted fields
  keep physical data but are absent from row/query I/O and ignored in views.
  Constraints/defaults are physical; field rewrites preserve row authorship.
- `GET /tables/{id}/schema` returns displayFieldId, fields/default/version,
  empty relations, visible views, schemaVersion and myLevel. Every field/
  display mutation increments schema version exactly once under metadata locks.
- `POST /views/{id}/query` accepts offset 0..1,000,000, limit default 100
  (1..100), optional single typed sort, includeCount default true and optional
  D-138 transient ordered fieldIds. It returns
  `{rows:[{id,fields}],fieldIds,total,schemaVersion}`. Count is null only when
  disabled. Sort has NULLS LAST in both directions, then row ID ascending.
  Configured live fields retain order; duplicate/unknown/deleted IDs are ignored;
  omitted user fields append by metadata order, system fields hidden unless
  explicitly visible. Configured sort applies unless overridden. fieldIds is
  not persisted and changes no authorization.
- Existing row routes: GET `/tables/{id}/rows/{rowId}` returns full `{id,fields}`;
  POST `/tables/{id}/rows` `{rows:[{fields}]}`; PATCH single row `{fields}`
  returns `{row,eventId}`; PATCH bulk `{rows:[{id,fields}]}`; DELETE bulk
  `{ids}` returns snapshots. Bulk insert/patch <=1000 rows/5000 supplied cells,
  512 KiB body; delete <=1000 IDs/64 KiB. Other requests remain 4096 bytes.
  Never silently truncate, split an atomic operation or change these limits.
- Bulk operations are atomic. Patches lock rows FOR UPDATE; later successful
  lock holder wins, with no row version. Bulk patch locks ascending numeric
  row IDs but responds in request order. Inserts omit unspecified values so
  physical defaults apply; one transaction timestamp initializes created_at/
  updated_at and both authorship UUIDs. Patches preserve creation values.
  Author values stay nullable lowercase UUIDs: no names/sharing-directory lookup.
- Read requires effective table read; writes require write/owner. Admin has
  no data bypass. Hidden/missing/trashed resources are 404, visible insufficient
  access is 403. Reauthorize writes uncached under D-080/D-099 locks. Table
  FOR SHARE protects row/query schema snapshots against field DDL FOR NO KEY
  UPDATE. Three-second lock timeout => ERR_DDL_LOCK_TIMEOUT; repeatable-read
  serialization => ERR_SCHEMA_CHANGED.
- Required/unique failures map to safe translated ERR_REQUIRED_FIELD/
  ERR_UNIQUE_CONFLICT; never expose physical names, values, constraints or PG
  text. Mutations need exact Origin, X-PT-CSRF:1, bounded known-member JSON,
  no-store and ten-second deadlines. Forced-password is 403; disabled/
  unauthenticated is 401. Preserve redacted errors and correlation IDs.
- Dynamic data SQL uses Squirrel, validated metadata and pgx.Identifier;
  values are parameters. Static metadata uses sqlc. No client name/type/
  options/expression/identifier interpolation.
