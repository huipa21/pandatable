## Binding contracts to preserve

- **Existing endpoints, unchanged.** `GET /auth/me` returns the user directly
  with role, prefs, `effectiveTimezone` and `mustChangePassword`;
  `PATCH /auth/me` takes `{displayName, locale, theme, timezone}` and returns
  `{user, eventId}`; `POST /auth/password` changes the password and revokes
  every session; `GET /meta/timezones` lists valid IANA zones. Do not add,
  rename or widen an endpoint, and do not introduce an admin-style profile API.
- **Timezone semantics (D-049, D-117, doc 09).** `timezone: null` means "use
  the app default" (`Asia/Shanghai` unless the admin changed it); values are
  validated against the PostgreSQL catalog; DB sessions stay UTC.
  `effectiveTimezone` is the resolved value and is what datetime rendering
  already consumes (D-117). Changing the team default must keep affecting only
  users without their own setting.
- **Password rules.** Changing the password revokes all sessions, including
  the current one; the old password must stop working and the new one must
  work. Forced-change users keep being redirected to `/change-password` before
  anything else, and the API keeps returning 403
  `ERR_PASSWORD_CHANGE_REQUIRED`. Rate limits, argon2id parameters and session
  sliding are unchanged.
- **Transport and security.** Mutations need exact Origin, `X-PT-CSRF: 1`,
  bounded known-member JSON, `no-store` and ten-second deadlines. Cookies stay
  HttpOnly/SameSite=Lax (Secure outside literal-local HTTP development, D-073).
  CSP and `nosniff` stay as shipped. Errors stay translated, redacted and
  correlated; never leak which identity exists on a failed login.
- **Frontend contracts.** Lazy route chunks, memory-only auth/nav state, the
  existing `AppLayout` header with language and theme toggles side by side,
  local preference persistence and the `web/src/api` request helpers stay as
  they are. Profile changes must keep the header toggles and the stored local
  preference coherent rather than forking a second preference mechanism.

## Implement T1.22

- Add a lazy, authenticated `/profile` page reachable from the existing
  session navigation: display name, language, theme and timezone, plus a link
  or section for the existing password change. Readers of their own profile
  are ordinary users; there is no admin-only capability here and no other
  user's profile is reachable.
- Send only changed fields (the T1.8 settings form is the precedent), show
  loading/error/retry and an explicit saved confirmation, and discard unsaved
  edits on reload. Timezone uses the live `/meta/timezones` catalog with an
  explicit "use app default" choice that sends `null`, not an empty string.
- Applying a locale or theme from the profile must update the running UI and
  the persisted local preference immediately and consistently with the header
  toggles, without a reload and without a second source of truth.
- A successful password change must land the user on the login route with the
  existing translated notice, because every session is revoked. Do not
  silently re-authenticate.
- Responsive and accessible at 390 px with no horizontal page scroll, labeled
  native controls, keyboard and touch support, both locales and light/dark. No
  user-visible string in source; add matching `en` and `zh-CN` keys.
- Do not add registration, email verification, SMTP, avatars, uploads, API
  tokens, SSO, public sharing, comments/history, realtime or any other
  Out-of-Scope feature. Do not add a dependency.
